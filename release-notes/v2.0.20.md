# Claudable Launcher v2.0.20

fix(v2.0.20): two-phase Ed25519 settlement for complete_job

Root cause of the recurring 'digest(text, unknown)' failure:
- TWO complete_job overloads existed; PostgREST picked the stale one
- that one had digest(p_output, 'sha256') with an untyped literal
- the migration file was not idempotent, so re-running it aborted on the
  first duplicate create policy and rolled back the whole transaction
- pgcrypto lives in schema 'extensions' and search_path was only public

Also fixed while verifying the flow end to end:
- verify_signature does not exist in pgcrypto -> replaced with a
  two-phase flow (complete_job stores an unverified receipt,
  settle-receipts Edge Function verifies Ed25519 via @noble/ed25519,
  settle_receipt() releases the reward)
- job_receipts.model_digest is NOT NULL but was missing from the INSERT
- prompt_hash/output_hash are bytea, not text (hex round-trip broken)
- inference_nodes.models is uuid[], not text[]
- status checks did not allow awaiting_verification / idle / busy
- trigger_updated_at() fired on inference_jobs which has no updated_at
- node_heartbeats partitions had no replica identity -> DELETE refused

Verified: 1 job -> pending receipt -> signature verified -> settled,
with tamper and job-id-swap negative controls both rejected.
